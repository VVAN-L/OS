## 三、实验整体逻辑分析

### 2.1 本章节的逻辑主线

本章围绕最小可执行内核和启动流程展开，重点讲解了操作系统初始化的启动流程、内核的内存分布和入口点设置、通过 OpenSBI 封装输入输出函数以及如何使用 Makefile 编译、如何使用 GDB 调试。

### 2.2 项目执行流

1. 加电复位，CPU从0x1000执行复位程序：完成最基本的环境准备并将控制权交给OpenSB，加载bootloader

2. 跳转至0x80000000执行bootloader：初始化处理器的运行环境，将编译生成的内核镜像文件加载到物理内存的0x80200000地址处

3. 执行位于0x80200000处的 entry.S：分配好内核栈，然后跳转到 kern_init

4. 执行kern_init：初始化内核环境，向用户提供可视化反馈。

## 四、实验内容与实现

### 练习1：理解内核启动中的程序入口操作

**负责人：** 2412934-王海沛、2412143-林家熠

**问题回答：**

指令 la sp, bootstacktop完成的操作：la（Load Address）是一条伪指令。该指令将链接脚本 kernel.ld 中定义的符号 bootstacktop 的地址加载到 sp（栈指针寄存器）中。在 GDB 调试中验证，执行该指令后，sp 寄存器的值变为了 0x80203000。

目的是：初始化内核栈

指令 tail kern_init完成的操作：

tail 是一条尾调用（Tail Call）伪指令。在 GDB 中通过 x/5i $pc 反汇编可以观察到，它被编译为了 j 0x8020000a <kern_init>（一条无条件跳转指令）。

它将 CPU 的控制权（PC 寄存器）跳转到 C 语言函数 kern_init 的入口地址处。

目的是：将控制权从汇编代码移交给 C 语言内核初始化程序。

### 练习2：使用GDB验证启动流程

**负责人：** 2411858-王钟岳

**调试过程：**
在 code 文件夹下分别使用两个终端，一个执行 make debug 启动 QEMU，一个执行 make gdb 启动 GDB 进行调试。在 kern_entry 处设置断点，单步调试并查看加电后最初执行的几条指令的地址与内容，跳转后执行至断点处。

**问题回答：**
硬件加电后最初执行的几条指令位于 0x1000 到 0x1010 。完成了最基本的环境准备，并跳转至 0x80000000。具体来说实现了：

1. 准备设备树（DTB）地址，存入寄存器 a1（addi a1, t0, 32）

2. 准备 CPU 核心编号（Hart ID），存入寄存器 a0（csrr a0, mhartid）

3. 跳转至 0x80000000，移交控制权（jr t0）

## 六、实验总结与收获

### 对操作系统的理解

1. 列出你们认为本实验中重要的知识点，以及与对应的 OS 原理中的知识点，并简要说明二者的含义、关系和差异

（1）内核栈初始化（la sp, bootstacktop）：
  本实验的含义：在汇编入口 entry.S 中，通过 la 伪指令将 bootstacktop 的地址赋给 sp（栈指针）寄存器，在 C 语言环境建立之前手动构建栈空间。
  
  对应的 OS 原理知识点：进程/线程的上下文与函数调用栈、内核栈。
  
  关系与差异：OS 原理课程中通常假设栈已经由操作系统或编译器自动维护，重点讲解栈的物理结构（向下增长）和上下文切换时的栈保存。而本实验展现了“从零开始建立栈”的底层过程——在加电初始化阶段，硬件并不提供栈，必须由汇编代码显式指定，这让抽象的“栈”概念变得极其具体。区别在于：原理课关注运行时的栈管理，而本实验关注启动时的栈构建。
  
（2）控制权交接与尾调用（tail kern_init）：
  本实验的含义：汇编代码通过 tail 伪指令跳转到 C 语言的 kern_init 函数，完成从汇编到高级语言的交接。
  
  对应的 OS 原理知识点：函数调用约定（Calling Convention）、程序编译与链接、代码段与数据段的划分。
  
  关系与差异：原理课侧重于用户态函数的调用规则（如寄存器传参、栈帧建立、返回地址保存）。本实验中的 tail 跳转因为目标函数 kern_init 被声明为 __attribute__((noreturn))，所以不需要压入返回地址（这是它与普通 call 的核心差异）。

2. 列出你们认为 OS 原理中很重要、但在本实验中没有对应上的知识点

链接脚本与栈的具体位置：bootstacktop 只是一个符号，它实际地址由链接脚本决定。栈空间多大、放在内存哪里，这些直接影响系统能否正常运行，但练习没有涉及。

### AI 协作开发的经验

[写出你们在与 AI 协作过程中实际收获的经验或者感悟]

1.理解 tail 的设计意图：tail kern_init 不保存返回地址，因为内核入口永不返回。AI让我看到代码背后的设计思路，而不只是语法。

2.把汇编翻译成“人话”：AI帮我理解 la sp, bootstacktop 不只是“加载地址”，而是给C语言函数准备栈空间——没有栈，kern_init 里的局部变量就没地方放。这让我真正懂了栈的意义。

3.真正的 OS 原理无法依赖 AI，必须亲手验证。AI 可以告诉我们 tail 是尾调用，但只有当我们亲手在 GDB 中用 si 单步执行，并看到 pc 跳转到 0x8020000a、sp 变成 0x80203000 时，才真正理解了从汇编到 C 语言交接那一刻的物理意义。AI 提供了“捷径”，但操作系统的底层逻辑需要我们自己去走完。
