### 功能模块：虚拟内存页操作功能

**负责人：** 2411858-王钟岳

#### 模块功能描述

**需要实现/修改的函数：**

```c
int page_insert(pde_t *pgdir, struct Page *page, uintptr_t la, uint32_t perm);
void page_remove(pde_t *pgdir, uintptr_t la);
```

**功能说明：**

这个模块负责在现有多级页表框架上完成最基本的映射维护，也就是把物理页挂到指定线性地址上，以及把已有映射安全地撤销掉。page_insert 负责建立或更新映射，不能简单覆盖旧项，而要正确处理原地址已经映射到同一物理页、或者原地址已经映射到其他物理页这两种情况；page_remove 负责删除映射，映射建立过程本身可能失败，调用路径必须能正确返回错误并保持系统状态干净。所有页表更新完成后都要考虑对应 TLB 失效，否则测试中会出现看似已更新、实际上仍在使用旧翻译结果的情况。

对外只需要提供“建立映射”和“撤销映射”两个动作。page_insert 成功时应让指定线性地址稳定映射到目标物理页，并把权限位设置为调用者要求的状态；失败时应返回 -E_NO_MEM，且不能留下半完成映射。

### Challenge：

**负责人：** 2411858-王钟岳

Q1：说明语句 local_intr_save(intr_flag); ... local_intr_restore(intr_flag); 是如何实现开关中断的。

A：两个宏通过控制 sstatus 寄存器中的 SIE 位实现开关中断。具体来说，local_intr_save(intr_flag) 保存 SIE 位并置 0，执行临界区代码，随后 local_intr_restore(intr_flag) 根据保存在 intr_flag 中的结果恢复 SIE 位。

Q2：get_pte() 函数中有两段形式类似的代码，结合 sv32、sv39、sv48 的异同，解释这两段代码为什么如此相像。

A：两段相似的代码分别是：

```c
pde_t *pdep1 = &pgdir[PDX1(la)];
if (!(*pdep1 & PTE_V)) {
    // 分配页表页、设置引用计数、清零，并写入 pdep1
}
```

```c
pde_t *pdep0 =
    &((pte_t *)KADDR(PDE_ADDR(*pdep1)))[PDX0(la)];
if (!(*pdep0 & PTE_V)) {
    // 分配页表页、设置引用计数、清零，并写入 pdep0
}
```

第一段代码的功能是通过 PDX1(la) 找到根页表中的表项，检查并按需创建下一级页表；第二段代码根据上一表项找到中间页表，再用 PDX0(la) 定位，检查并按需创建下一级页表。

两段相似是因为：Sv32、SV39、Sv48都是多级页表，页表各层结构相似，向下走一级所做的操作也相同。按照这种展开写法，Sv32 只需一段“定位或创建下一级页表”的逻辑，Sv39 需要两段，Sv48 则需要三段。

Q3：目前 get_pte() 函数将页表项查找和页表页分配合并在一个函数里，你认为这种写法好吗？有没有必要把两个功能拆开？

A：这样的写法是合理的，但在复杂系统下可能会产生问题。当前 get_pte() 通过参数 create 的值区分查找和分配两种行为。这样写的好处在于需要分配时能复用页表查找的逻辑进行遍历；但缺点是返回 NULL 既可能表示页表不存在也可能表示分配失败，且分配失败没有进行回滚。
